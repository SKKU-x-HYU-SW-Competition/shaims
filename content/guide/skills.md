# 스킬 시스템

[api.md](api.md)에서 설명한 기본 조작 위에 **스킬 시스템**이 얹혔습니다.
이 페이지는 **스킬 때문에 새로 생긴 것들**만 다룹니다 — 기본 API와 필드 의미는
api.md 그대로이고, 여기서는 다음 네 가지만 설명합니다:

1. 스킬 때문에 추가된 스냅샷 필드
2. 스킬을 발동하는 새 리턴 필드 `skillX`
3. 게이지가 차고 깎이는 규칙
4. 유일한 스킬 「발톱」의 효과와 회피법

**스킬을 안 써도 됩니다.** 원래 3필드(`x`/`y`/`hit`)만 돌려주는 봇도
아무 수정 없이 계속 돌아갑니다.

## 전체 스냅샷 (스킬 필드 포함)

```json
{
  "tick": 12345,
  "side": "LEFT",
  "self": {
    "x": 120, "y": 244, "state": 0, "frameNumber": 3, "divingDirection": 0,
    "lyingDownDurationLeft": -1,
    "gauge": 70,
    "claw": null
  },
  "opp": {
    "x": 300, "y": 180, "state": 1, "frameNumber": 5, "divingDirection": 0,
    "lyingDownDurationLeft": -1,
    "gauge": 30,
    "claw": { "centerX": 120, "framesUntilStrike": 12, "framesLeftActive": 0 }
  },
  "ball": {
    "x": 216, "y": 140, "xVelocity": -3, "yVelocity": 6,
    "expectedLandingPointX": 340, "isPowerHit": false
  },
  "meta": {
    "score": { "self": 7, "opp": 6 },
    "isPlayer2Serve": false, "rallyFrameCount": 42
  },
  "config": { "tickFrameGroupSize": 3 }
}
```

## 전체 리턴 (skillX 포함)

```js
return { x: 0, y: 0, hit: 0, skillX: 300 };  // x=300 위치로 발톱 발동
return { x: -1, y: 0, hit: 1 };                // skillX 생략 = 발동 안 함
return { x: 0, y: 0, hit: 0, skillX: null };   // 명시적 null도 발동 안 함
```

Python도 완전 동일 (필드 이름 그대로):

```python
return {'x': 0, 'y': 0, 'hit': 0, 'skillX': 300}
```

## 새로 추가된 스냅샷 필드

### `self.gauge` / `opp.gauge` — 현재 게이지 (0 ~ 100 정수)

스킬 발동에 쓰는 자원입니다. 공을 잘 넘길수록 채워지고, 스킬을 쓸 때 소모됩니다.
매치 시작 시 0으로 시작하며, **랠리가 끝나도 유지됩니다** (매치가 시작할 때만
0으로 리셋). 초반에 깔끔하게 받아둔 것이 후반의 스킬로 돌아오는 구조입니다.

상대 게이지도 그대로 보여줍니다. "지금 상대가 발톱을 쏠 수 있는가"를 봇이
알아야 회피를 준비할 수 있고, 어차피 화면 상단에 양쪽 게이지 바가 그려지는
정보라 숨길 이유가 없습니다.

충전·소모 규칙은 아래 [게이지 시스템](#게이지-시스템) 절 참고.

### `self.claw` / `opp.claw` — 예고 중인 발톱

**시전자 기준으로 붙는 필드입니다.** 발톱의 피해자는 항상 시전자의 상대이므로:

|  | 의미 |
|---|---|
| `opp.claw` | **상대가 쏜 것 = 나를 노리는 것.** 회피 판단은 이걸 봅니다 |
| `self.claw` | 내가 쏜 것. `null`이 아니면 재발동이 거절됩니다 |

발동 중이 아닐 때는 `null` (Python은 `None`). 발동 중일 때는:

| 필드 | 뜻 |
|---|---|
| `centerX` | 발톱 x범위의 **중심** 좌표 (0 ~ 432) |
| `framesUntilStrike` | 발톱이 터지기까지 남은 프레임. `0`이면 이미 터졌고 연출만 남은 상태 |
| `framesLeftActive` | 연출이 사라지기까지 남은 프레임. 이게 0이 되고 나서야 시전자가 재발동 가능 |

### `self.lyingDownDurationLeft` / `opp.lyingDownDurationLeft`

`state === 4`(누워있음/기절)일 때만 의미 있는 값입니다. **다시 움직일 수 있게
되기까지 `값 + 2` 프레임**이 남았다는 뜻 (엔진 내부 관례로 +2가 붙습니다).
다른 state에서는 의미 없는 값이 남아 있으니 무시하세요.

내가 발톱에 맞아 기절한 경우, 이 값으로 "몇 프레임 뒤에 다시 움직일 수 있는지"를
계산해서 깨어난 직후의 첫 행동을 미리 계획해둘 수 있습니다.

## 새로 추가된 리턴 필드: `skillX`

숫자를 넣으면 그 x좌표를 중심으로 발톱을 예약합니다. 넣지 않거나 `null`이면
그 틱은 스킬을 쓰지 않은 것으로 처리됩니다.

```js
return { x: 0, y: 0, hit: 0, skillX: 300 };
```

- **범위**: `0 ~ 432` (코트 전체). 범위 밖 값은 코트 안으로 클램프됩니다.
  자기 진영에 쏘는 것도 막지 않습니다 (손해일 뿐 반칙은 아닙니다).
- **발동 실패는 조용히 무시**됩니다: 게이지 부족, 이미 발동 중, 시전자가 기절
  상태 등. **실패해도 게이지는 안 깎입니다.**
- **응답 1건당 최대 1회.** 같은 `skillX`를 여러 틱 계속 돌려줘도 게이지가
  반복 소모되지는 않지만, 발동 조건이 갖춰지면 자동으로 나가버립니다.
  "언제 쓸지"는 직접 조건을 걸어 결정하는 편이 좋습니다.
- **숫자가 아닌 값**(문자열, `NaN`, `Infinity`)이면 그 틱의 **발동만** 무시되고
  `x`/`y`/`hit`는 정상 적용됩니다. 전체 무입력이 되지는 않습니다.

## 게이지 시스템

**한 줄 요약**: 공을 잘 넘길수록 채워지고, 스매시를 쓰면 조금 깎입니다.

플레이어별로 게이지를 하나씩 갖고, 공 접촉이 일어날 때마다 다음 규칙으로
증감합니다:

| 접촉 종류 | 증감 |
|---|---|
| 서브 (랠리의 첫 접촉) | **0** |
| 상대에게서 넘어온 공을 받음 | **+15** |
| 같은 진영에서 이어 침 — 이 진영에서 **2번째** 접촉 | **0** (페널티 없음) |
| 같은 진영에서 이어 침 — 이 진영에서 **3번째부터** | **-5** |
| 위 접촉이 **파워히트(스매시) 성공**이었으면 추가로 | **-10** (가산) |

몇 가지 짚어둘 것:

- 같은 진영에서 리시브 후 세팅으로 한 번 더 만지는 것(2번째 접촉)까지는
  페널티 없이 허용됩니다. 랠리 중 정상적인 리시브+세팅이 굴러가도록 열어둔
  것이고, **3번째부터** -5가 붙어 시간 끌기를 억제합니다.
- 파워힛 페널티는 접촉의 기본 증감에 **가산**됩니다. 예시:
  - 리시브를 그대로 스매시로 넘김 → `+15 + (-10) = +5`
  - 리시브 + 세팅 + 3번째를 스매시로 넘김 → `+15 + 0 + (-5 - 10) = 0`
- **다이빙 접촉은 파워히트가 아닙니다.** 공중에서 점프하며 치는 스매시(엔진에서
  `self.state`가 `2`가 되는 접촉)만 이 -10 페널티가 붙습니다.

### 넘기는 데 쓴 터치 수별 순증감 (파워히트 없음 기준)

| 넘긴 터치 수 | 순 증감 |
|---|---|
| 1터치 리턴 | +15 |
| 2터치 리턴 (리시브+세팅) | +15 |
| 3터치 리턴 | +10 |
| 4터치 리턴 | +5 |

5터치 이상은 발생할 수 없습니다 — 같은 진영에서 5번째 접촉이 일어나면 그
진영이 자동 실점하는 **터치 제한 규칙**이 따로 있어서 랠리가 그 전에 종료됩니다.

### 게이지 관리 감각

- **스매시를 남발하면 게이지가 별로 안 찹니다** (`+15 - 10 = +5`밖에 못 벌음)
- **깔끔한 리시브 리턴(1~2터치, 스매시 없음)이 가장 이득** (+15)
- 발톱 한 번에 55가 필요하니, 대략 **깔끔한 리시브 4번 정도 벌어야 한 번
  쓸 수 있는** 자원

## 스킬「발톱」(`claw`)

**요약**: 게이지 55를 소모해 상대 코트의 특정 x범위에 **1초 뒤** 발톱을
떨어뜨립니다. 그 순간 그 범위 안에 있는 상대는 **1.80초간 움직일 수 없고**
(공중이었어도 즉시 땅으로 떨어져서) 그 자리에 누워 있습니다.

### 발동 조건

리턴에 `skillX`를 넣어 보냈을 때 아래를 **전부** 만족하면 발동됩니다:

- `self.gauge >= 55`
- `self.claw === null` (이미 예고 중이 아님)
- `self.state`가 `0` 또는 `1` (기절/승리/패배 모션 중이 아님)
- 랠리 진행 중 (서브 대기·랠리 종료 직후가 아님)

하나라도 안 맞으면 그 틱의 발동만 무시되고, 게이지는 그대로 남습니다.

### 타임라인

발동 시점을 T=0(프레임 기준)이라고 두면:

```
T = 0        게이지 55 차감, 발톱 예약. 상대 화면에 예고 표시 시작
T = 0~24     예고 25프레임 (약 1초). 상대가 x범위 밖으로 이동해서 회피 가능
T = 25       발톱 판정. 범위 안에 있는 상대 → state=4로 기절 시작
T = 25~34    발톱 연출 10프레임 (판정은 T=25 한 번뿐, 이후는 그림만)
T = 35       시전자 재발동 가능 (self.claw = null이 됨)
```

피해자는 T=25부터 **45프레임(1.80초)** 동안 누워 있고, 그 뒤 자동으로 일어나
다시 움직일 수 있습니다.

### 판정 범위 — **x축만** 봅니다

발톱은 자기 x범위 안의 **모든 y**(코트 전체 높이)를 판정합니다. **점프로는
못 피합니다.** 좌우 이동만이 회피 수단이고, 판정 순간에 공중에 있어도 x범위
안이면 땅으로 끌려 내려와서 기절합니다.

발톱 폭은 **60 픽셀**(중심 기준 ±30)입니다. 플레이어 히트박스 반폭이 32이니:

```js
// 나(self)가 이 발톱에 맞을 x 범위인지
var claw = s.opp.claw;
if (claw && claw.framesUntilStrike > 0) {
  var danger = 60 / 2 + 32;   // 발톱 반폭 30 + 플레이어 반폭 32 = 62
  var offset = s.self.x - claw.centerX;
  if (Math.abs(offset) <= danger) {
    // 위험 범위 안. 남은 framesUntilStrike 안에 좌우로 벗어나야 함
  }
}
```

**남은 프레임의 마지막 몇 개는 이미 늦었다고 봐야 합니다.** api.md에서 설명한
1틱 파이프라인 지연 + `tickFrameGroupSize`(3) 만큼, 실제 회피 여유가 스냅샷에
찍힌 `framesUntilStrike`보다 최대 6프레임 정도 짧습니다. **`framesUntilStrike`가
6 이하면 이번 발톱은 못 피한다고 보고 다음 수를 준비**하는 편이 낫습니다.

### 회피 예시 코드

```js
function dodgeDirection(s) {
  var incoming = s.opp.claw;
  if (!incoming || incoming.framesUntilStrike <= 0) return 0;
  var danger = 60 / 2 + 32;
  var offset = s.self.x - incoming.centerX;
  if (Math.abs(offset) > danger) return 0;         // 이미 안전
  if (offset === 0) return s.side === 'LEFT' ? -1 : 1;
  return offset > 0 ? 1 : -1;                       // 밀리는 방향으로 계속 이동
}
```

플레이어 이동 속도는 프레임당 6픽셀이므로, 예고 25프레임 동안 최대 약 150픽셀
움직일 수 있습니다. 위험 반경(≈62)의 두 배가 넘으니, 걸어서 나가면 대부분
피해집니다.

### 조준 — 지금 자리에 쏘면 대부분 회피됨

25프레임(1초)의 예고 때문에, **상대의 현재 x**만 노리면 대부분 걸어서 피합니다.
잘 맞추려면 두 가지 접근이 있습니다:

**낙하지점 리드 사격.** 공이 상대 진영에 떨어질 낙하지점(`ball.expectedLandingPointX`)을
노리되, **공이 땅에 닿기까지 남은 시간이 발톱의 25프레임과 비슷할 때** 발동합니다.
그러면 상대가 리시브하러 반드시 서야 하는 자리와 발톱이 터지는 자리가 일치합니다.
회피하려면 실점을 각오하고 공을 포기해야 하니 강력합니다.

**속도 기반 예측.** 상대의 x속도(직전 스냅샷의 `opp.x`와 비교)를 구해서
`opp.x + vx * 25`를 조준합니다. 다만 상대가 25프레임 안에 방향을 바꾸면 빗나갑니다.

### 기절 상태에서

`self.state === 4`이면 이번 틱에 어떤 조작을 보내도 무시됩니다. `skillX`를
넣어도 발동은 무시되고 게이지도 안 깎입니다. 남은 시간은
`self.lyingDownDurationLeft + 2` 프레임입니다.

기절 시간이 결코 짧지 않으니, **깨어난 뒤 첫 행동을 미리 계산해두는 것**이
중요합니다. 예를 들어 "45프레임 뒤에 공이 어디에 있을지" 계산해서 깨어나자마자
그 방향으로 바로 이동하도록 준비해두는 식.

### 발동 확인

발동 성공 여부는 **다음 틱의 `self.claw`** 를 보면 알 수 있습니다:

- `self.claw === null` → 발동 실패 (조건 불충족). 게이지는 그대로.
- `self.claw`가 객체 → 발동 성공. `framesUntilStrike`가 25에서 카운트다운을
  시작합니다.

### 키보드 플레이어

키보드로 조작할 때는 좌표를 입력할 방법이 없어서, **발동 키를 누르면 그 순간
상대의 x 위치를 중심으로 자동 발동**됩니다. 왼쪽 플레이어는 `C` 키, 오른쪽
플레이어는 오른쪽 `Shift` 키.

봇 vs 키보드 대결에서도 스킬은 양쪽 다 쓸 수 있습니다. 단, **기본 탑재 AI는
스킬을 쓰지 않습니다** (맞기만 함). 봇 vs 기본AI일 때는 봇 쪽만 발톱을 발동합니다.

---

**정리**: 새 스냅샷 필드 세 종류(`gauge`, `claw`, `lyingDownDurationLeft`)와
새 리턴 필드 하나(`skillX`)를 알면 스킬 시스템 전부입니다. 나머지는 [api.md](api.md)의
기본 API와 완전히 동일하게 동작합니다.
